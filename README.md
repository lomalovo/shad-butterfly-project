# Детекция бабочек: сравнение готовых моделей

Этап 5 финального проекта по курсу Crowdsourcing. Три готовые модели запускаются без обучения на 400 фото команды и на экзаменационном наборе: Grounding DINO tiny, OWLv2 base и Qwen3-VL-2B-Instruct. Все запуски локальные и последовательные, платные API не используются.

## Что в этой папке

Здесь всё, что нужно для воспроизведения результатов: код (`src/`, `scripts/`, `tests/`), конфиги, таблица фото команды, golden set, экзаменационный датасет Контеста и все результаты (`outputs/`). По сырым ответам моделей из `outputs/raw/` и `outputs/exam/raw/` предсказания, метрики и файл для Контеста пересчитываются без запуска моделей.

Чего здесь нет:

- фото (около 550 МБ и 300 МБ) — их качает `src/download.py` со сверкой sha256, команды ниже;
- выгрузки разметки `Все-результаты-ШАД-817/`: в ней ID исполнителей и ревьюеров, она остаётся у команды. Из неё берутся только `data/golden/candidate_339.jsonl` и `candidate_282.jsonl`, они уже лежат в `data/golden/`. Пересобрать их можно командой `make_golden.py --export <путь к выгрузке>`;
- `.venv`, её нужно создать заново.

Порядок воспроизведения: установка, скачать фото, `scripts/run_team.sh` (все модели на фото команды), `scripts/evaluate_team.sh` (метрики), `scripts/run_exam.sh` (файл для Контеста). Если запускать только `evaluate_team.sh`, он считает метрики по уже сохранённым ответам моделей.

## Установка

Нужен Python 3.12. Qwen3-VL требует свежий `transformers`.

```bash
uv pip install --python .venv/bin/python -r requirements.txt
```

## Запуск

```bash
scripts/run_team.sh                      # инференс всех конфигов на фото команды + постобработка
scripts/evaluate_team.sh                 # метрики и подбор порога по data/golden/candidate_339.jsonl -> outputs/eval/
OUT=outputs/eval_282 scripts/evaluate_team.sh data/golden/candidate_282.jsonl
scripts/run_exam.sh data/exam/images submission/dataset.jsonl   # итоговый конфиг: инференс, файл для Контеста и его проверка
```

`run_exam.sh` по умолчанию прогоняет детекцию `final` (на M3 Pro около 25 минут на 400 фото), потом проверку рамок `final_verify` (около 4 минут). Другие конфиги можно добавить: `CONFIGS="final owlv2_neg" scripts/run_exam.sh <папка>`. Файл для Контеста: `outputs/exam/submission_final_verify.jsonl`.

То же по шагам:

```bash
.venv/bin/python src/infer.py --config configs/owlv2.yaml --images data/images --out outputs/raw/owlv2.jsonl
.venv/bin/python src/postprocess.py --raw outputs/raw/owlv2.jsonl --config configs/owlv2.yaml --out outputs/preds/owlv2.jsonl
.venv/bin/python src/evaluate.py --golden data/golden/candidate_339.jsonl --preds outputs/preds/*.jsonl
.venv/bin/python src/verify.py --config configs/final_verify.yaml --images data/exam/images --raw outputs/exam/raw/final.jsonl --out outputs/exam/raw/final_verify.jsonl
.venv/bin/python src/postprocess.py --raw outputs/exam/raw/final_verify.jsonl --config configs/final_verify.yaml --out outputs/exam/submission_final_verify.jsonl
.venv/bin/python src/validate_submission.py --sub outputs/exam/submission_final_verify.jsonl --ids submission/dataset.jsonl
```

## Устройство

| Файл | Что делает |
| --- | --- |
| `src/infer.py` | сырые предсказания с низким порогом: рамки, score, label, время на фото, сырой текст Qwen. Перезапуск дообрабатывает только фото без результата или с ошибкой |
| `src/postprocess.py` | порог, class-agnostic NMS, обрезка по [0, 1], формат Контеста |
| `src/metrics.py` | TP/FP/FN через максимальное паросочетание (`linear_sum_assignment`), суммирование по всему набору |
| `src/evaluate.py` | лидерборд, метрики по группам, per-image дамп в `outputs/eval/` |
| `src/sweep.py` | подбор порога и NMS по golden set без перезапуска модели |
| `src/verify.py` | проверка рамок Qwen: вырезка каждой рамки с меткой из `keep_labels` и вопрос той же модели, есть ли там бабочка или моль. Скор — P(yes) / (P(yes) + P(no)) |
| `src/bootstrap.py` | бутстреп по фото: разница F1@0,5 двух вариантов предсказаний на golden |
| `src/make_golden.py` | golden из выгрузки разметки команды в формат пайплайна |
| `src/proxy_stats.py` | число рамок по предварительному полю `count`, использовалось до появления golden |
| `src/validate_submission.py` | проверка файла для Контеста: все id ровно по разу, `photo_id` целый, нет лишних полей и повторных ключей, числа конечные, координаты в [0, 1], ширина и высота > 0, размер ≤ 5 МиБ |
| `src/visualize.py` | рамки на картинках: golden зелёным, модели красным, голубым, оранжевым |
| `tests/` | юнит-тесты метрики, парсера ответа Qwen и постобработки (`.venv/bin/python -m pytest tests`) |

Модель получает только изображение. Колонки CSV используются только для разбивки метрик по группам.

## Форматы

Предсказания и посылка: одна строка JSONL на фото, координаты нормированы в [0, 1].

```json
{"photo_id": 123, "boxes": [{"left": 0.1, "top": 0.2, "width": 0.3, "height": 0.4}], "error": null}
```

Пустой `boxes` значит «бабочек нет». Ошибка обработки пишется в `error` и в `outputs/logs/errors.jsonl` со всеми попытками, пустым списком она не подменяется. Golden set в том же формате, загрузчик `load_golden` в `src/evaluate.py`.

Полные хеши ревизий лежат в конфигах.

Конфиги `*_neg` передают моделям правило инструкции «гусениц, куколок и других насекомых не размечать» через отрицательные метки. Модель ищет и бабочек, и то, что размечать нельзя, а рамки с меткой не бабочки и не моли отбрасываются до порога и NMS (`keep_labels` в конфиге, без учёта регистра). Длинную инструкцию DINO и OWLv2 не понимают, им можно дать только короткие названия объектов:

- у OWLv2 метка рамки — запрос с наибольшим скором;
- у DINO метка — фраза, у токенов которой самый высокий скор. Стандартная функция `transformers` склеивает метки в строку вроде `butterfly moth`, поэтому метка считается в `src/infer.py`. Рамки и скоры при этом те же, это проверено на старом конфиге;
- Qwen3-VL подписывает каждую рамку сам, одной меткой из списка в промпте. Прежний промпт `qwen3vl` тоже содержит все правила, но в виде запрета.

Сырые предсказания сохраняются с порогом 0,1 для DINO и 0,02 для OWLv2, итоговый порог подбирается постобработкой.

Окружение: Apple M3 Pro, 18 ГБ, macOS 26, устройство `mps`, Python 3.12.15, torch 2.15.0, transformers 5.23.0. DINO и OWLv2 в float32, Qwen3-VL в bfloat16 без квантования.

Преобразования изображения: `ImageOps.exif_transpose(...).convert('RGB')`, дальше стандартный процессор модели. У OWLv2 процессор паддит до квадрата. Боксы переводятся через `target_sizes=(max(h, w), max(h, w))`, это проверено визуально на вытянутых фото. Qwen3-VL получает картинку, ужатую до не более чем 1 048 576 пикселей (`max_pixels`), и отвечает в шкале 0–1000. Генерация жадная, до 1024 новых токенов. Ответ парсится через `json.loads`, а если не вышло, полные объекты `bbox_2d` достаются регэкспом. Координаты вне 0–1000 и вырожденные рамки отбрасываются и пишутся в журнал. Неразобранный ответ считается ошибкой.

Дополнительные варианты постобработки, без перезапуска моделей:

- `dino_butterfly_moth__nms_off`: тот же инференс, NMS выключен (эксперимент 2);
- `qwen3vl__nms_0.9` и `qwen3vl_neg__nms_0.9`: убирают точные повторы рамок, когда Qwen зацикливается (на 1 фото из 400 с прежним промптом и на 2 с новым).

### Итоговая конфигурация

`configs/final_verify.yaml`, с 20.11.2026. Qwen3-VL-2B-Instruct, ревизия `89644892e4d85e24eaac8bacfd4f463576704203`, bfloat16 без квантования, `mps`. Картинка через `exif_transpose` и RGB, не больше 1 048 576 пикселей. Промпт просит обвести бабочек, молей, гусениц, куколок и других насекомых и подписать каждого. Остаются рамки с меткой `butterfly` или `moth`. Генерация жадная, до 1024 токенов.

Дальше каждая оставшаяся рамка вырезается с полями 10% и отдаётся той же модели с вопросом `Is there an adult butterfly or moth in this image? Answer yes or no.`. Скор рамки — P(yes) / (P(yes) + P(no)) по первому токену ответа. Рамки со скором ниже 0,02 отбрасываются, потом class-agnostic NMS 0,3 и обрезка по [0, 1].

Выбрана по правилу из задания: лучший F1@0,5 на golden команды, 0,943 против 0,921 у прежнего `final` (без проверки). Порог проверки подобран на тех же 339 фото, но любой порог от 0,01 до 0,9 лучше `final` на обоих вариантах golden, а при бутстрепе по фото выигрыш положителен в 99,9% выборок. Обоснование и эксперименты — в [EXPERIMENT.md](EXPERIMENT.md), эксперимент 6.

### Что видно по ошибкам

- Qwen3-VL лучший по F1, но в 5–9 раз медленнее детекторов. Почти все одиночные бабочки найдены, recall 0,96.
- Слабое место всех моделей — точность рамок: F1@0,75 заметно ниже F1@0,5 (у `final` 0,75 против 0,92). У `final` F1@0,75 на одиночных бабочках 0,82, на мелких объектах 0,55, на фото с несколькими бабочками 0,52.
- Фото с несколькими бабочками сложнее всего: у `final` F1@0,5 = 0,82 против 0,97 на одиночных. Таких фото в golden только 15, оценка шумная. Основные ошибки — пропуск одной особи из пары и зацикливание Qwen на фото с 10 бабочками.
- DINO почти не отличает бабочек от других насекомых и гусениц: лишние рамки на 89–95% фото без бабочек.
- Главный источник лишних рамок у Qwen — зацикливание: модель повторяет рамку с постоянным шагом, пока не кончатся токены. Проверка по вырезке убирает почти все такие рамки на фоне, но не те, что идут среди настоящих бабочек или по мелким жёлтым листьям.

- На 2 фото ответ упёрся в лимит токенов (18953, 97701). На 18953 модель зациклилась и выдала 29 рамок вдоль стебля растения. После проверки осталось 7: на мелких вырезках с жёлтыми лепестками модель видит бабочку.
- Сокомандники посмотрели ответы `final` и нашли 8 подозрительных фото, разбор — в EXPERIMENT.md, эксперимент 6. Проверка рамок появилась после этого просмотра, но порог выбран только по golden команды, правило одно для всех фото, и та же ошибка (зацикливание) есть на golden. Вручную ответы на экзамене не правились, этого не позволяет условие.
- 3 из 8 фото (27844, 59045, 342746) повёрнуты в EXIF. В повёрнутом кадре, как фото показывает браузер, рамки стоят на бабочках, а на неповёрнутой картинке съезжают. Handoff требует координаты в той ориентации, которую видели исполнители, то есть в повёрнутой, так что эти фото не трогались.
- Глазами проверены 12 случайных фото и все 7 повёрнутых: рамки на месте, пчёлы, жуки и гусеницы не обведены. До и после проверки на 8 фото от команды: `outputs/viz/exam_verify/`.

**Моли.** В условии Контеста написано: «Моли, другие насекомые, гусеницы, куколки и тени не размечаются». В handoff и в правилах разметки команды моли размечаются, исключение молей из ранней версии задания отменено. `final` выбран по golden команды, где моли размечены. На случай, если эталон экзамена всё-таки без молей, есть вариант из того же прогона, который оставляет только метку `butterfly`: `outputs/exam/submission_final_no_moth.jsonl` (215 рамок, тоже проходит проверку, конфиг `configs/final_no_moth.yaml`). Минус варианта: Qwen называет `moth` и дневных толстоголовок, на golden команды так подписано 16 толстоголовок из 17. На golden команды `final_no_moth` даёт F1@0,5 = 0,863 против 0,921.

**Решение 20.11.2026: в Контест идёт файл с молями.** Сначала это был `outputs/exam/submission_final.jsonl`. После эксперимента 6 его заменяет `outputs/exam/submission_final_verify.jsonl`, тоже с молями: он лучше на golden команды и соответствует правилам разметки из handoff. Вариант без молей, сделанный из `final`, оставлен только для справки.

```bash
.venv/bin/python src/postprocess.py --raw outputs/exam/raw/final.jsonl --config configs/final_no_moth.yaml --out outputs/exam/submission_final_no_moth.jsonl
```

До golden модели сравнивались по прокси из предварительного поля `count` в CSV: `outputs/proxy_stats.md`.
